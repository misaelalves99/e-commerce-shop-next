# Evidence Plan

## Purpose

This document defines the visual and technical evidence required before the project is presented as a publication-ready case study.

## Visual evidence candidates

Capture application states that demonstrate real implemented behavior, such as:

- home/catalog experience;
- product detail;
- authentication entry;
- cart;
- checkout;
- successful order creation state;
- persisted order history;
- account/profile experience.

## Technical evidence candidates

Capture or reference:

- successful automated test execution;
- successful type check;
- successful lint execution;
- dependency audit result;
- successful production build;
- GitHub Actions quality result;
- deployment result.

## Privacy and security rules

Evidence must not expose:

- passwords;
- authentication tokens;
- cookies;
- Firebase Admin credentials;
- revalidation credentials;
- local environment values;
- private browser/session information.

## Publication rule

Runtime assets already used by the application are not automatically case-study evidence.

Case evidence should be intentionally captured, reviewed, and selected for publication.
